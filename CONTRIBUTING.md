# Praca w repozytorium

1. Wybierz zgłoszenie z celu sprintu i przypisz się w tablicy.
2. Utwórz krótkotrwałą gałąź z `master`, np. `feat/12-dodanie-podrozy`, `fix/23-pusta-data` albo `docs/27-uruchomienie`.
3. Zapisuj spójne zmiany zgodnie z Conventional Commits, np. `feat(podroze): dodaj ekran nowej podrozy`.
4. Otwórz pull request do `master`. Podaj zgłoszenie, kryteria akceptacji oraz wynik testu.
5. Poproś inną osobę o przegląd. Przed scaleniem uwzględnij uzgodnione uwagi, potwierdź przejście testów i sprawdź warunki ukończenia objęte zmianą.
6. W końcowym PR wpisz `Closes #12`, podstawiając numer kompletnego zgłoszenia. W częściowym PR wpisz `Powiązanie: #12`.
7. Po scaleniu potwierdź działanie na `master` i odśwież stan karty. Przy błędzie zapisz wynik i pozostaw zgłoszenie otwarte lub otwórz je ponownie.

W opisie PR wskaż uczestników pracy w parach i dodaj dowody ręcznych testów, jeżeli są częścią kryteriów.
